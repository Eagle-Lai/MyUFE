# 2026-08-20 工作日志

## UFE 插件旧版 Unity API 编译错误修复（MyprojectDemo 项目）

### 问题
工作区 g:\MyprojectDemo（Unity 2020.3.17f1 + UFE 格斗游戏插件）存在大量编译错误，全部源于 UFE 插件使用了 Unity 2018.2 已移除的旧 API：
- `GUIText` / `GUITexture`（旧 GUI 系统）
- `Network` / `NetworkView` / `NetworkPlayer` / `NetworkConnectionError` / `NetworkPeerType` / `NetworkMessageInfo` / `NetworkDisconnection` / `NetworkStateSynchronization` / `RPCMode` / `RPC`（旧 UNET 网络系统）
- `MovieTexture`（视频，旧 API）
- `AudioClip` 无参构造函数（编辑器脚本）

### 修复方案（兼容层 + using 别名）
新建 `Assets/UFE Addons/Compatibility/UFELegacyAPICompat.cs`，提供与原 API 兼容的自定义类型（后缀 Compat）：
- `GUITextCompat`（MonoBehaviour，OnGUI 渲染文本）
- `GUITextureCompat`（MonoBehaviour，OnGUI 绘制纹理）
- `NetworkCompat`（静态类，方法返回 ConnectionFailed，legacy 网络已不可用）
- `NetworkPlayerCompat` / `NetworkConnectionErrorCompat` / `NetworkPeerTypeCompat` / `NetworkMessageInfoCompat` / `NetworkDisconnectionCompat` / `NetworkStateSynchronizationCompat` / `RPCModeCompat` / `RPCCompat` / `NetworkViewCompat`

然后在各业务文件顶部用 `using GUIText = GUITextCompat;` 等别名指向兼容类型，无需改业务逻辑。涉及文件：
- UFE.cs、ControlsScript.cs、MultiplayerAPI.cs、NullMultiplayerAPI.cs、NetworkGameScreen.cs、DefaultBattleGUI.cs
- LanDiscovery.cs、LegacyNetworkMultiplayerAPI.cs、NetworkController.cs、LocalPlayerController.cs、RemotePlayerController.cs
- GlobalEditorWindow.cs（GUITexture 别名）
- CharacterEditorWindow.cs / MoveEditorWindow.cs（`new AudioClip()` → `AudioClip.Create(...)`）

### 视频播放重写
`VideoIntroScreen.cs` / `StoryModeVideoScreen.cs` 的 LoadMovie 从 MovieTexture+GUITexture 重写为 `UnityEngine.Video.VideoPlayer`（CameraNearPlane 渲染），保留原注释和音乐恢复逻辑。

### 关键经验
1. **必须把新文件加入 Assembly-CSharp.csproj 的 Compile Include**（Unity 生成的 csproj 是显式列表），否则 IDE 语言服务器报 CS0246。
2. csproj 修改后 IDE 语言服务器可能需要重新加载项目/窗口才识别新文件；MSBuild 实际编译（`dotnet msbuild`）可先验证代码正确性。
3. 语言服务器错误会逐步刷新，最终全工作区 lint 只剩过时 API warning（PrefabUtility/Selectable.allSelectables 等，非 error）。
4. 项目正在运行 Unity 编辑器进程（多个 Unity 进程），Library/ScriptAssemblies 中 dll 时间戳可判断 Unity 编译状态。

## 第三次修复：重新打开 Unity 后 package-manager-ui 编译错误（当天 15:50）

### 问题
用户重新关闭并打开 Unity 后，控制台大量 `error CS0246: UxmlNamespacePrefixAttribute could not be found`，全部来自 `Library\PackageCache\com.unity.package-manager-ui@1.9.11`。

### 根因
`com.unity.package-manager-ui@1.9.11` 是 **Unity 2018.2 时代的独立包**（package.json 里 `"unity": "2018.2"`），使用了已移除的 `UnityEditor.Experimental.UIElements` 旧 API（UxmlNamespacePrefix 特性）。而 Unity 2020.3 的 Package Manager UI 是**编辑器内置功能**（Window > Package Manager），不该在 manifest.json 中显式依赖这个旧包。该依赖是从旧项目升级继承来的。

### 修复
1. `Packages\manifest.json` 移除 `"com.unity.package-manager-ui": "1.9.11"` 依赖行
2. `Packages\packages-lock.json` 移除对应的 `com.unity.package-manager-ui` 依赖块
3. 删除 `Library\PackageCache\com.unity.package-manager-ui@1.9.11` 目录
4. 用 Python `json.load` 验证两个 JSON 语法合法

### 关键经验
- **Unity 2020.3 中 Package Manager UI 内置**，manifest.json 不应有 `com.unity.package-manager-ui` 依赖；出现该包编译错误（UxmlNamespacePrefix 等 Experimental.UIElements API）时直接移除依赖 + 删缓存。
- Unity 编辑器运行时持有旧编译状态（Temp\UnityTempFile-* 的 rsp 编译清单仍含已删包文件），manifest 修改后**必须重新加载项目/重启 Unity** 才会重新解析包并清掉旧错误。
- IDE 语言服务器不编译 PackageCache 包，所以 read_lints 看不到这些 error；要通过 `Temp\UnityTempFile-*` rsp 内容和 `Logs\Editor.log` 判断。
- 其它旧包 com.unity.ads@2.0.8/analytics@2.0.16/purchasing@2.0.3 在 2020.3 仍可用，无兼容问题，不必动。
